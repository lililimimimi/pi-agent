# 模块 19：看改动（diff）

**目标：** agent 每轮改了哪些文件，都能在应用里列出来，并能看每个文件的具体改动。写代码时能放心确认结果。

**依赖：** 模块 18 通过。

## 方案

- **改动来源**：agent 每次调用 edit 或 write 工具时，记下文件路径，以及修改前的内容。
- **显示位置**：每轮回复结束后，在这条回复下面显示"本轮改动了 N 个文件"，点开看每个文件的 diff。
- **不是 git 仓库也能用**：不依赖 git，直接用记下的修改前内容对比。

## 步骤

- [ ] 后端：在 pi-bridge 的 edit、write 工具执行前，记录文件路径和修改前内容，通过 SSE 事件发给前端。
- [ ] 后端测试：一次 edit 后，事件里有正确的路径和修改前内容。
- [ ] 前端：store 收集本轮的改动；回复结束后，在消息下方显示改动列表。
- [ ] 前端：点击文件，显示 before / after 的对比（新增行、删除行有颜色区分）。
- [ ] 前端测试：给定一组改动，列表和对比结果正确。
- [ ] 手动验证：让 agent 改一个文件，列表出现，diff 内容和实际改动一致。

## 验收

- [ ] 改动列表在每轮结束后出现，不会混入上一轮的改动
- [ ] 新建文件（之前不存在）显示为全部新增
- [ ] 测试通过，类型检查通过
- [ ] 我审核后才 commit

## 风险

- 文件很大时 diff 可能很长，列表要可以折叠。
- 同一文件在一轮里被改多次，要显示"最初"和"最后"的对比，而不是每次改动都单独列出。
